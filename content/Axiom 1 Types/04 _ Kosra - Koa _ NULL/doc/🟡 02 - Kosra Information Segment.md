
## Attaching information / Providing information

Sometimes we can attach information for an entity
such as length, size, duration, time, color, brightness, pitch, quantity, mass, adjectives and more.

To attach information to an entity,
we will attach an "information segment" behind the entity we want to describe.
an information segment is made up of 3 parts
- start information segment marker
- trait list
- end information segment marker

here we use /Sævæ/ from  [[🟡 01 - Request and Provide]] as a way to mean "given the following information"

>[!note] Nested Information Segment
>Sometimes it is possible to have items inside the trait list to attached with it's information segment.
>
>The function of /Svæk/ and /Svok/ can act as a mechanism to avoid ambiguity in syntax.
>
>In theory of computation, Ambiguitity happens when a string can be generated by using different parse trees.
>
>Astralica is built and designed based on Computer Science, therefore grammatic Ambiguity is one of the Design goals to fix and avoid.

here we will take a javascript object as an example :

```javascript
{
	label : size
	value : big
}
```

this is a single Javascript item
here it can be interpreted as an information segment item
also, a single noun or entity can have multiple information segment items
basically, a Kosra information segment item has 2 parts :
- a label : to know what trait we are describing, a size ? color ? quantity ?
- a value : to know how does that trait behaves, varies between different traits or labels.

let's say we want to describe 3 small red balls :

```js
ball
[
	{ trait:size , value:small } ,
	{ trait:color , value:red } ,
	{ trait:qty, value:3 }
]
```

this can be translated into Astralica as :

```
Ji-ball //the entity we want to describe

Svæk //start describing

	Kaklana //size
	Sklæ //crank small
	
	LiTa //color
	Rahaka //red
	
	Kla //quantity
	Na //3
	
Svok //done describing
```

or in a single line typed :

```
Ji-ball Svæk Kaklana Sklæ LiTa Rahaka Kla Na Svok
```

## Requesting information / Interrogative Words

instead of attaching information,
we can request information instead, at this point, we can change
/SæVæKoa/ to /SæVaKoa/, literally "start requesting for the following traits"
or cropped : /Svak/

| :---------------------------: | :-----------------------------------------------------------------: | :-------------------------------: | :----------------------------------------------------------------: |
| **(Slot : Entity goes here)** |                         ![[Kosra.png\|50]]                          | **(Slot : Trait List goes here)** |                         ![[Kosra.png\|50]]                         |
|               ^               |                        ![[Request.png\|50]]                         |                 ^                 |                    ![[Request - Copy.png\|50]]                     |
|                               | /Sæyanævata - Kosra/<br>/Sva-Koa/<br>/Svak/<br>"Start info-segment" |                                   | /Sæyanævato - Kosra/<br>/Svo-Koa/<br>/Svok/<br>"Stop info-segment" |

let's say we heard someone has a adopted a litter of cats and we wanted to ask :
- how many they are (quantity)
- what color are they (color)
- and how big / small they are (size)

we can have the following in Astralica :

```
Koixonya //Cat
Svak //start asking
	Klari //qty
	Litaraka //color
	Kakla //size
Svok //done asking
```

## Providing exactly 1 information item only

Sometimes, the trait list only has just one item, so instead of /Svæk ... Svok/ or /Svak ... Svok/,
we can go with /Svæki .../ or /Svaki .../ then followed by an information item

## Natural Languages approach

in English, this can be achieved by using "WHERE"
SQL and Math uses this a lot
*"this this this will happen where bla bla bla"*

in Bahasa Melayu, this is done by using the word "yang"
BM : "Saya ada sebuah kotak yang besar di rumah saya"
Lit : "I have a box that is big at house my"
